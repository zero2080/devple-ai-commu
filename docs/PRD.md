# PRD — 2D 도트 아트 가상공간 채팅 서비스

> 문서 버전: 1.3 (2026-09-30, 모바일 뷰포트 보장·아바타 목록)
> 상태: 확정
> 관련 문서: ARCHITECTURE.md, DOMAIN.md, API_CONTRACT.md, GRAPHICS.md, CONVENTIONS.md, CLAUDE.md

## 1. 개요

90년대 2D 도트 아트 스타일의 가상공간에 회원들이 캐릭터로 입장해, 맵 위를 이동하며 대화하는 폐쇄형 실시간 커뮤니티 웹 서비스.

- 운영자 승인을 거친 회원만 입장 가능
- 모든 접속자는 **하나의 공용 맵**에 동시에 존재 (추후 다중 맵 확장 가능하도록 설계)
- 대화는 **캐릭터 간 거리**에 따라 전달 범위가 달라짐

## 2. 프로젝트 범위

| 구분 | 내용 |
|---|---|
| 이번 프로젝트 | **프론트엔드 (React + Vite + TypeScript SPA)** |
| 후속 프로젝트 | 백엔드 API 서버 — 본 프론트의 `API_CONTRACT.md`를 구현 기준으로 삼음 |
| 개발 방식 | Contract-First. 프론트는 Mock 서버 기반으로 선행 개발 |

## 3. 목표 / 비목표

### 목표
- 동시 접속 수백 명 규모에서 부드러운 캐릭터 이동과 1초 이내 메시지 전달
- 운영자 승인 기반의 신뢰 가능한 멤버십 (친구 관계 없이도 안전하게 DM 가능한 이유)
- 백엔드가 그대로 구현할 수 있는 명확한 REST + SSE 계약

### 비목표 (이번 범위 밖)
- 음성/화상 통화
- 파일·이미지 업로드 (바이너리 전송 자체를 금지)
- 네이티브 모바일 앱, 브라우저 푸시 알림
- 종단간(E2E) 암호화
- 다중 맵 간 이동 (설계상 확장 여지만 확보)
- 사용자 제작 아바타/맵 에디터

## 4. 사용자 역할

| 역할 | 권한 |
|---|---|
| 방문자 | 가입 신청만 가능 |
| 회원 | 입장, 이동, 대화, DM, 그룹 채팅 |
| 운영자 | 회원 권한 + 가입 승인/거절, 회원 정지, 공지 |

## 5. 핵심 기능

### 5.1 가입 / 인증
1. 가입 신청: 이메일, 닉네임, 연락처 입력
2. 운영자 승인 대기 (신청자는 상태 확인 페이지 조회 가능)
3. 승인 시 이메일로 **접근 키** 발급
4. 접근 키로 로그인 → JWT 발급 (Access + Refresh)
5. Access 만료 시 Refresh로 무중단 갱신, Refresh 만료 시 재로그인
6. 접근 키를 잃으면 **운영자에게 요청** → 운영자가 재발급 → 기존 키 무효 + 새 키 이메일. 사용자 셀프 재발급은 없음 (폐쇄형 원칙)

### 5.2 캐릭터
- 기본 제공 도트 아바타 중 선택 (초기 8종). 선택 가능한 목록은 서버가 정한다. 가입 승인 시 하나가 배정되고 이후 변경 가능
- 캐릭터 머리 위에 닉네임 표시
- 상태(온라인/자리비움) 표시 — 5분간 입력이 없으면 자동 자리비움, 입력 시 복귀

### 5.3 이동
- 입력: 방향키 / WASD 연속 이동, 마우스 클릭·터치 탭으로 목적지 지정 후 자동 이동(경로 탐색). 캐릭터를 클릭·탭하면 이동 대신 프로필 카드
- 타일 기반 맵, 벽·오브젝트 충돌 처리
- **캐릭터 간 충돌**: 한 타일에는 캐릭터 1명만. 목적지에 이미 다른 캐릭터가 있으면 그 직전 타일까지만 이동. 이동 중 경로가 막히면 멈추지 않고 경로만 다시 계산
- 다른 접속자의 캐릭터 위치를 실시간 반영
- 화면은 내 캐릭터를 중심으로 카메라 스크롤
- **채팅 입력 중 이동**: 입력창에 포커스가 있으면 키보드 이동 비활성. `Enter`로 입력창 포커스, `Esc`로 캔버스 복귀. 클릭/터치 이동은 항상 가능

### 5.4 근접 대화 (공개)
- 내 캐릭터 기준 **반경 N타일** 내 접속자에게만 전달 (기본값 N=5, 서버 설정값)
- 범위는 **타일 단위**로 계산하여 화면 확대/축소(줌)에 영향받지 않음
- 캐릭터 머리 위 **말풍선**으로 표시, 일정 시간 후 사라짐
- 하단 대화 로그 패널에도 누적 표시

### 5.5 DM (1:1)
- 특정 회원과 1:1 대화
- 상대가 **근접 범위 안**에 있으면 말풍선 노출 — 공개 대화와 **다른 배경색**
- 상대가 범위 밖이면 **전달은 되고**, 말풍선 없이 **DM 패널로만 수신**
- DM 대상 지정: 캐릭터 클릭 → 프로필 카드 → DM, 또는 닉네임 검색. 친구 관계 불필요

### 5.6 그룹 채팅
- 회원이 그룹을 생성하고 멤버 초대
- 위치와 무관하게 그룹 멤버 전원에게 전달
- 별도 채팅 패널(탭)로 표시, 안 읽은 메시지 수 표시
- 그룹장 권한: 초대, 강퇴, 그룹 해산 (타인 메시지 삭제 권한은 없음)

### 5.7 사용자 조회
- 맵 위 캐릭터 클릭(터치) → 프로필 카드 (닉네임, 아바타, 상태 메시지) + "DM 보내기" 버튼
- 닉네임 검색으로 접속 여부와 무관하게 사용자 조회 가능
- 친구 관계 개념 없음. DM은 사용자 ID만 알면 누구에게나 가능

### 5.8 메시지 공통
- **유니코드 텍스트만** 지원 (이모지 포함). 이미지·파일 등 바이너리 첨부는 어떤 경로로도 불가
- 텍스트 안의 **URL은 허용**. 말풍선과 채팅 목록에서 본문은 그대로 보여주고, 링크는 **별도 "링크 열기" 버튼**으로 제공 (본문 내 인라인 클릭 링크 없음)
- **전송된 메시지는 수정·삭제 불가 (불변).** DM만 상대가 읽기 전이면 회수 가능
- 이전 메시지 무한 스크롤 (DM, 그룹)
- 공개 근접 대화는 세션 중에만 유지, 서버 저장 여부는 백엔드에서 결정

### 5.9 운영자 콘솔
- 가입 신청 목록 조회, 승인 / 거절 (거절 사유 입력)
- 회원 정지 / 해제
- 접근 키 재발급 (기존 키·세션 즉시 무효)
- 전체 공지 발송

## 6. 비기능 요구사항

| 항목 | 기준 |
|---|---|
| 동시 접속 | ~300명 |
| 메시지 지연 | 1초 이내 |
| 이동 반영 지연 | 300ms 이내 (배칭 주기 포함) |
| 렌더링 | 60fps 목표, 최소 30fps 유지 |
| 브라우저 | 최신 Chrome / Safari / Edge (데스크톱 우선, 모바일 브라우저는 열람·채팅 가능 수준) |
| 화면 크기 | 데스크톱: 맵 20×15타일 이상 표시. 모바일: **내 근접 대화 범위 전체**(반경 5 → 11×11타일)를 항상 표시. 최소 지원 폭 360 CSS px (GRAPHICS 1.2) |
| 접근성 | 키보드만으로 모든 기능 사용 가능. 이동(방향키/WASD)과 채팅 입력(Enter/Esc) 간 포커스 전환이 명확해야 함 |

## 7. 기술 결정 요약 (상세는 ARCHITECTURE.md)

| 항목 | 결정 | 비고 |
|---|---|---|
| 프론트 | React + Vite + TypeScript SPA | |
| 렌더링 | 순수 Canvas API | 외부 게임 엔진 미사용 |
| 실시간 수신 | SSE (탭당 연결 1개, 모든 이벤트 다중화) | 브라우저 HTTP/1.1 연결 제한 대응 |
| 실시간 송신 | REST | 이동은 일정 주기로 묶어서 전송 |
| 인증 | 접근 키 로그인 + JWT (Access/Refresh) | |
| 공간 | 단일 맵 | 맵 ID를 계약에 포함해 확장 여지 확보 |

- 사용자 차단 기능 필요 여부 (친구 기능 제거로 함께 제거됨, 필요 시 별도 추가)
