2. 이제 되는 것

  • 접근: /admin은 운영자만 들어가요. 일반 회원은 월드로 돌아가요. 콘솔로 옮겨도 실시간 연결과 자리비움 추적은 끊기지 않아요.
  • 가입 신청: 대기 중·승인됨·거절됨 필터로 보고, 승인하면 회원 목록에 바로 나타나요. 거절은 사유(1~200자)를 반드시 적어야 하고, 거절됨 필터에서 사유를 볼 수 있어요. 다른 운영자가 먼저 처리한 신청이면 "이미 처리된 신청이에요"라고 안내하고 목록을 새로 받아요.
  • 회원: 전체·활성·정지 필터. 정지하면 그 사람은 월드에서 바로 사라져요(연결이 끊기므로). 해제와 접근 키 재발급도 할 수 있어요. 정지와 재발급은 되돌리기 어려워서 한 번 더 확인해요.
  • 공지: 채팅 메시지와 같은 규칙(빈 내용·길이 초과 막기)으로 보내요. 받은 사람 화면 상단에 최신 1건이 배너로 뜨고 닫을 수 있어요. 공지는 링크 목록이 없는 형식이라 링크 버튼 없이 텍스트로만 보여요.

결정 (사용자, 2026-10-01): A안. ROADMAP 11b단계로 추가해 진행해요.

PRD 5.1은 "가입 신청(이메일·닉네임·연락처) → 운영자 승인 대기(신청자는 상태 확인 페이지 조회 가능)"를 요구하고, 계약(POST /signup, GET /signup/{requestId})과 Mock도 준비돼 있어요. 그런데 ROADMAP 1~12b단계 어디에도 이 화면이 없어요. CLAUDE.md 규칙상 단계에 없는 기능은 제가 임의로 넣지 않고 여쭤요.

선택지내용대가
A. 11b단계로 추가 (추천)12a 전에 작은 단계로. 로그인 없이 들어가는 /signup(입력 검증은 API_CONTRACT 2.1)과 /signup/{requestId}(대기·승인·거절 사유 표시), 로그인 화면에서 링크. 운영자 콘솔과 짝이 맞아 전체 흐름을 E2E로 확인할 수 있어요반나절 정도의 작업 (추정, 정확도 중간)
B. 12a단계에 합치기옷장 화면과 함께아바타 파이프라인과 관계없는 일이 섞여요
C. 당분간 범위 밖운영자 콘솔은 시드 신청으로만 확인실제 사용자가 가입할 방법이 없어요

chat에도 같은 내용으로 알렸어요(docs/handoff/to-chat/2026-09-30-step11-signup-gap.md).

7. 남은 것과 한계

  • Mock에서 정지를 풀어도 가짜 사용자가 월드에 다시 나타나지 않아요. 가짜 사용자는 스스로 다시 로그인하지 않기 때문이고, /__mock/reset으로 되돌려요.
  • 모바일 콘솔에서는 처리 버튼이 표 오른쪽에 있어서 가로로 스크롤해야 보여요.
  • 공지는 이번 세션에 받은 최신 1건만 보여요. 지난 공지를 조회하는 API는 계약에 없어요.
  • 회원이 아닌 사람이 /admin에 들어갔을 때 월드로 돌려보내는 동작은 단위 테스트로만 확인했어요. Mock에는 운영자 계정 하나뿐이라 E2E로는 확인할 수 없어요.
  • E2E는 Chromium에서만 돌렸고 Safari는 확인하지 않았어요.
