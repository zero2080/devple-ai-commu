2. 이제 되는 것

  • 신청: 이메일·닉네임·연락처를 입력해요. 보내기 전에 서버와 같은 규칙으로 먼저 확인해요. 닉네임은 앞뒤 공백을 뺀 2~12자, 보이지 않는 문자는 쓸 수 없고, 연락처는 숫자·하이픈 8~20자예요. 서버가 거절하면 그 이유를 해당 칸 옆에 보여 줘요. 이미 쓰는 닉네임(대소문자만 달라도 같은 닉네임)이나 이미 가입·신청한 이메일도 해당 칸에 알려 줘요.
  • 상태 확인: 신청하면 신청 번호가 들어간 주소로 이동해요. 이 주소를 저장해 두면 언제든 다시 볼 수 있고, 다른 기기에서는 신청 번호를 입력해 찾을 수 있어요. 신청 번호는 주소에만 두고 브라우저에 저장하지 않아요.
  • 접근 키: 새 형식(XXXXX-XXXXX-XXXXX-XXXXX)이에요. 소문자로 치거나 하이픈 없이 쳐도 서버가 맞춰 줘요(Mock도 같은 규칙). Mock 데모 키는 DEMO0-00000-00000-00000으로 바뀌었어요.

11b E2E(e2e/phase2-signup.spec.ts)는 세 가지를 확인해요.

  • 로그인 화면에서 신청 → 대기 → 소문자·하이픈 없는 키로 운영자 입장 → 콘솔에서 승인 → 상태 화면 승인
  • 대소문자만 다른 닉네임, 대기 신청과 같은 이메일 → 해당 칸에 409 안내
  • 신청 번호로 거절 사유 확인, 없는 번호 안내

4. 인박스 처리 (계약 2.1)

  • chat 문서 반영: API_CONTRACT 2.1, DOMAIN 2.1, handoff README(백엔드 저장소 devple-ai-commu-server가 세 번째 에이전트, 백엔드 인박스 to-server/).
  • Mock을 계약에 맞췄어요.
    • 가입 검증 오류 사유(필수·길이·형식·잘못된 문자)와 EMAIL_TAKEN
    • 닉네임 중복은 대소문자·유니코드 정규화 무시(가입·내 정보 수정)
    • 접근 키 정규화
    • 나에게 DM 400
    • 이동 요청의 필드별 오류(다른 맵·정수가 아닌 좌표 등)
  • 오류 문구 EMAIL_TAKEN과 필드 사유 6종을 추가했어요.
  • 규칙 추가: 계약 자산(맵 JSON·catalog.json·palette.json)을 바꾸면 백엔드 인박스에 알려요. CLAUDE.md와 CONVENTIONS에 적었어요. 백엔드가 이 파일의 사본으로 위치·외형을 검증하기 때문이에요.
  • 닉네임 줄바꿈: 계약이 분명하지 않아 chat에 물었고, 작업 중에 DOMAIN 2.2로 확정됐어요 — 닉네임은 한 줄, 줄바꿈·탭 포함 제어 문자 전부 금지(메시지는 줄바꿈 허용 유지). 이미 같은 규칙으로 구현해 두어 코드 변경은 없어요.
