개발 서버에서 캐릭터가 안 보이던 문제

devple-ai-commu · 2026-09-30 · 작성: Claude Code · 이전: 8단계 결과

결론. pnpm dev로 띄운 화면에서 맵만 보이고 캐릭터가 하나도 없었어요. 앱 코드 문제가 아니라 개발용 Mock 서버를 찾아가는 주소 문제였어요. Vite 프록시가 localhost:5174를 IPv6 ::1로 먼저 풀었는데, 이 머신에서는 다른 프로젝트(VRINGON-WEB)의 Vite가 그 주소를 쓰고 있었어요. 그래서 실시간 연결 티켓 요청이 엉뚱한 서버로 가서 404를 받았어요. 프록시와 Mock 서버를 모두 127.0.0.1로 고정해서 해결했어요. 실행 중이던 개발 서버에도 바로 반영돼 캐릭터 20명이 다시 보여요.

결정이 필요한 것 1건. 화면 위쪽 끝에 있는 사람의 말풍선이 캔버스 위로 잘려요(3절). 선택지와 추천안을 적어 두었어요.

1. 무엇이 보였고 왜 그랬나

확인결과
포트 점유 실측 (lsof)[::1]:5174 = VRINGON-WEB의 Vite, *:5174 = 이 프로젝트 Mock 서버. 둘이 충돌 없이 함께 떠 있었어요

브라우저 로그인 직후POST /api/v1/sse/ticket → 404, "ticket request failed, will retry" 반복

기존 README는 "5174가 점유돼 있으면 MOCK_SSE_PORT=5199로 바꾸라"고 안내했어요. 하지만 이번처럼 다른 서버가 ::1에만 붙어 있으면 Mock 서버는 에러 없이 뜨기 때문에 점유 사실 자체를 알 수 없었어요. E2E는 5199를 써서 이 문제를 잡지 못했어요.

2. 고친 것

  • 주소 고정: SSE_MOCK_HOST = '127.0.0.1'(src/mocks/data/config.ts)를 Mock 서버의 listen 주소와 Vite 프록시 대상으로 함께 써요. E2E의 Mock 호출과 준비 확인 URL도 같은 주소로 바꿨어요. 준비 확인 URL이 localhost면 다른 서버의 응답을 받고도 "준비됨"으로 넘어갈 수 있었어요.
  • 점유 시 즉시 실패: Express 5는 listen 실패를 콜백 인자로 넘기는데, 기존 코드는 인자를 무시하고 "listening"을 찍었어요. 이제 127.0.0.1:포트가 점유돼 있으면 원인과 MOCK_SSE_PORT=5199 pnpm dev 안내를 찍고 exit 1로 끝나요.
  • README·ROADMAP의 확인 명령을 127.0.0.1로 고쳤어요.

3. 결정 필요: 위쪽 끝 말풍선 잘림

좌우 가장자리는 7단계에서 이미 처리했어요(몸통을 안쪽으로 밀고 꼬리는 발화자를 가리킴). 위쪽 가장자리에 대한 규칙은 GRAPHICS 5.2에 없어요.

선택지장점대가
A. 그대로 둔다변경 없음. 전체 내용은 로그에 있음반경 끝에서 여러 줄로 말하면 앞줄이 안 보임
B. 캔버스 안으로 밀어 내린다 (추천)좌우 처리와 같은 방식이라 일관되고 구현이 작음밀려 있는 동안 발화자의 닉네임·머리를 덮음. GRAPHICS 5.2 "닉네임 항상 표시"에 예외 한 줄이 필요
C. 들어갈 자리가 없으면 캐릭터 아래로 뒤집는다닉네임을 가리지 않음꼬리가 위로 가는 새 모양과 규칙이 필요하고, 아래쪽 캐릭터를 덮음
