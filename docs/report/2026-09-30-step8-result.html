2. 이제 되는 것

  • 프로필 카드: 캐릭터를 클릭·탭하면 닉네임·아바타 색·접속 여부·상태 메시지. "DM 보내기"(본인 제외), 닫기, Esc. 빈 곳을 누르면 카드가 닫히고 이동해요.
  • DM 보내기: 카드의 버튼이나 DM 탭의 닉네임 검색(접속 안 한 사람도)으로 스레드를 열고 바로 입력해요. 위치와 상관없이 전달돼요.
  • DM 받기: 보낸 사람이 내 근접 반경 안이면 그 사람 머리 위에 하늘색 DM 말풍선, 밖이면 말풍선 없이 DM 탭 안 읽음만 늘어요. 스레드를 열면 읽음 처리돼요.
  • 회수: 상대가 아직 안 읽은 내 메시지만 "회수"로 지울 수 있어요. 이미 읽혔으면 버튼 대신 "읽음"이 보이고, 경합으로 늦게 누르면 안내 문구가 떠요.
  • 무한 스크롤: 스레드는 최근 50개부터, 위로 스크롤하면 이전 50개씩 붙고 보던 위치를 지켜요.
  • Mock: 내가 DM을 보내면 가짜 상대가 5초 뒤 읽고 짧게 답해요. 브라우저 콘솔에서 __devpleMock.dmFrom('u_03', '안녕')으로 가짜 DM을 받아 볼 수 있어요(README).

4. 인박스 처리 (chat 요청)

  • 말풍선 위치를 GRAPHICS 5.2 공식(꼬리 끝 = 프레임 상단 − (2 + 닉네임 줄 높이 + 1))으로 맞췄어요. 지금은 플레이스홀더 닉네임이라 − 11, 12단계에서 − 15가 돼요.
  • 픽셀 폰트 글자는 line-height: 1. 폰트에는 호환 자모 94자와 요청 문장부호가 이미 있어 재빌드가 필요 없었어요(크기 변화 0).
  • API_CONTRACT 1.5에 맞춰 group.removed에 left 추가, 신청 거절 사유 필수, 자기 정지 403. 결정 리포트 7번을 해결로 표시했어요.

5. 진행 중 발견해서 고친 것

문제처리

탭("근접"·"DM")과 글자 수 카운터가 12px로 그려져 배지 숫자가 잘 안 보임. GRAPHICS 5.1 "em × 줌만" 위반 (스크린샷 검토로 발견)24px(em × 줌)으로. 모바일 가로 넘침 검사 재통과

6. 남은 것과 한계

  • 가까운 두 사람의 말풍선이 겹쳐요. 내 DM과 옆 사람의 답이 동시에 떠 있으면 최신 것이 위로 와서 앞 말풍선을 가려요(GRAPHICS 5.2의 겹침 순서). 규칙을 바꾸려면 chat 결정이 필요해요.
  • DM 말풍선 색 #2ce8f5는 임시값이에요. GRAPHICS에 기록해 달라고 chat에 요청했어요(docs/handoff/to-chat/2026-09-30-dm-bubble-color.md).
  • 프로필 카드는 캔버스 왼쪽 위를 가리는 오버레이예요. 사용자가 연 일시적인 창이라 보장 영역 규칙의 예외로 ARCHITECTURE에 적었어요.
  • Mock에서는 상대가 가짜라, 내가 읽었을 때 상대에게 가는 chat.dm.read는 흉내 내지 않아요. 다중 탭 동기화 E2E도 아직 없어요.
  • E2E는 Chromium에서만 돌아요(Safari 미검증).
