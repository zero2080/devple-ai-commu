결론. 인박스에 온 아바타 v2 계약 변경을 먼저 반영하고, ROADMAP 10단계를 완료했어요. 아바타 v2는 2등신 캐릭터, 장착 아이템 7슬롯, 프리셋 색 선택이고, 계약 문서(DOMAIN·API_CONTRACT·GRAPHICS) 2.0이 기준이에요. 캐릭터는 이제 외형마다 다른 색으로 그려지고, 프로필 카드에 미리보기가 나와요. 10단계에서는 5분 동안 입력이 없으면 자리비움으로 바뀌고, 오래 끊겼다가 돌아오면 목록과 월드를 다시 받아요. 정지되면 로그인 화면으로 보내고 안내해요. 검증 결과는 단위 테스트 341건, domain 커버리지 100%, E2E 23건(두 번 연속 통과)이에요. 새로 결정할 사항은 없어요.

1. 아바타 v2 반영 (인박스)

  • 계약: avatarId를 없애고 appearance(피부색·머리색 + 7슬롯, 슬롯마다 주색·보조색)로 바꿨어요. 서버 설정의 avatarIds는 avatarOptions(아이템·램프 목록)로 바뀌었어요.
  • 외형 검증: API_CONTRACT 2.2 표와 같은 규칙으로 판정해요. 키가 없거나 필수 슬롯이 비면 required, 목록에 없으면 unknown, 슬롯에 맞지 않는 아이템이면 slot_mismatch예요. domain/appearance.ts에 넣었고, Mock과 나중에 만들 옷장 화면이 같이 써요.
  • 화면 규격: 프레임이 24×40이 되면서 닉네임과 말풍선 위치가 8px 올라갔어요. 모자를 바꿔도 닉네임이 움직이지 않아요. 클릭 판정은 몸 박스(16×32)로 해서, 옆 사람의 모자나 소품을 눌러 엉뚱한 프로필이 열리지 않아요.
  • 자산 데이터: palette.json(32색, 램프 31종)과 catalog.json 골격(아이템 42종)을 만들었어요. "램프 색은 팔레트 안에만 있다", "키 색과 팔레트 색이 겹치지 않는다", "아이템 ID 접두사 = 슬롯"을 테스트로 고정했어요.
  • 발견: presence.updated 핸들러가 3단계 이후 계속 파싱만 하고 있었어요. 그래서 닉네임·외형·자리비움이 바뀌어도 다른 사람 화면에 반영되지 않았어요. 이번에 월드와 사용자 캐시에 반영하게 연결했어요.
  • 로드맵: 옛 12단계를 12a(아바타 합성 파이프라인 + 옷장, 자리표시 레이어로 끝까지 동작)와 12b(실제 도트 그림·타일셋)로 나눴어요. 옷장은 chat이 추천한 A안이에요. 내 프로필 카드와 툴바 버튼에서 여는 모달이에요.

2. 10단계 화면

3. 이제 되는 것

  • 자리비움: 키보드·마우스·휠·터치 입력이 5분 없으면 서버에 away를 보내고, 다시 입력하면 바로 online을 보내요. 탭을 백그라운드로 보내는 것만으로는 바뀌지 않아요. 채팅을 읽기만 하는 사람을 위한 규칙이에요. 전송이 실패하면 상태를 그대로 두고 다음 입력이나 만료 때 다시 보내요.
  • 재동기화: 서버가 sync.required를 보내거나 연결이 60초 넘게 끊겼다가 돌아오면 실행해요. 월드 접속자를 다시 받고, DM·그룹 목록과 그룹 상세를 새로 받아요. 열려 있던 대화는 최신 페이지부터 다시 받아요. 여러 번 겹쳐 불려도 한 번만 실행돼요.
  • 정지: 실시간 연결로 정지 알림을 받거나, 어떤 요청이든 "정지된 계정" 응답(403)을 받으면 바로 세션을 끝내요. 연결을 다시 열지 않고, 로그인 화면에 안내를 띄워요. 다시 로그인하면 폼에 같은 이유가 한 번만 표시돼요.
  • 표시: 연결 배지에 내 자리비움, 캐릭터 반투명, 프로필 카드의 "자리비움"(다른 사람).
  • Mock: __devpleMock.suspendMe()(운영자가 나를 정지), POST /__mock/emit으로 sync.required 발생, E2E용 __devple.setAwayTimeoutMs(ms).

10단계 E2E(e2e/phase2-session.spec.ts)는 세 가지를 확인해요.

  • 입력 없이 두면 서버와 배지가 자리비움으로 바뀌고, 키를 누르면 online으로 돌아와요.
  • 화면에 알리지 않고 서버에만 새 DM 대화를 만든 뒤 sync.required를 보내면, 월드 접속자 요청이 나가고 목록에 그 대화가 나타나요.
  • 정지되면 로그인 화면과 안내가 뜨고, 2.5초를 기다려도 연결을 다시 열지 않아요. 다시 로그인해도 거부돼요.

단위 테스트로는 여섯 가지를 고정했어요.

  • 입력마다 타이머를 다시 걸지 않아요(마우스 이동 100번에 타이머 재설정 2회 이하).
  • 전송이 실패하면 다시 보내요.
  • 보내는 도중에 들어온 입력도 반영해요.
  • 60초 기준은 첫 끊김부터 재요(끊긴 뒤 재시도가 이어져도 첫 시각 기준).
  • 재동기화는 겹쳐 불려도 한 번만 돌아요.
  • 로그인 요청의 403은 세션 종료를 부르지 않아요.

6. 남은 것과 한계

  • 60초 넘게 끊겼다가 다시 연결될 때의 재동기화는 단위 테스트로만 확인했어요. E2E로 실제 60초를 기다리지는 않았어요.
  • Mock에서는 페이지를 새로고침하면 브라우저 안 상태가 초기화돼서, 정지된 사용자가 다시 들어올 수 있어요. 실제 서버와는 무관한 Mock의 한계예요.
  • 자리비움 중에 연결이 끊겼다 다시 이어질 때 서버가 내 상태를 어떻게 복원하는지는 계약에 없어요. 클라이언트는 다음 입력 때 online을 다시 보내므로 실사용 문제는 없다고 봤어요(추정, 정확도 중간).
  • 캐릭터는 아직 색 도형이에요. 실제 레이어 합성과 옷장 화면은 12a단계예요.
  • E2E는 Chromium에서만 돌렸고 Safari는 확인하지 않았어요.
