12a단계 결과: 아바타 파이프라인 + 옷장

devple-ai-commu · 2026-10-01 · 작성: Claude Code · 이전: 11b단계 결과

결론. 12a단계를 마쳤어요. 실제 그림 대신 코드가 만든 자리표시 그림으로 전체 경로가 끝까지 동작해요. 그림 파일을 읽고, 외형마다 한 번 합성해 색을 바꾸고, 방향·걷기 동작으로 그려요. 옷장에서 바꾸면 저장되고, 자산 검수도 자동으로 돌아요. 닉네임은 캔버스 글자에서 말풍선과 같은 픽셀 폰트의 화면 요소(DOM)로 바뀌었어요. 12b에서 같은 경로에 실제 그림 파일만 넣으면 돼요. 검증 결과는 단위 테스트 449건, domain 커버리지 100%, E2E 33건(두 번 연속 통과)이에요. 걷기 중 화면 갱신 간격은 p95 16.8ms로 기준 20ms 안이에요. 결정이 필요한 것은 1건(CI 도입)이에요.

0. 결정해 주세요

결정CI(자동 검사 서버)를 둘까요?

규칙 문서(CONVENTIONS)는 "CI 통과"를, 그래픽 문서(GRAPHICS 8장)는 "자산 검수를 CI에 넣는다"를 전제해요. 그런데 이 저장소에는 CI 설정(.github/workflows)이 없어요. 지금은 모든 검사를 제가 커밋 전에 로컬에서 돌리고 있어요. 그래서 다른 사람(또는 다른 에이전트)이 검사 없이 올린 변경은 막지 못해요.

선택지내용영향
A (추천)GitHub Actions 워크플로 1개 추가: 푸시·PR마다 lint · typecheck · test · check:assets. E2E(Playwright)는 시간이 걸리니 나중에 따로 추가해요깨진 커밋을 PR에서 바로 알 수 있어요. GitHub Actions 사용량을 써요(공개 저장소면 무료, 비공개면 월 무료 한도 안일 가능성이 높아요 — 추정, 정확도 중간)
B지금처럼 로컬에서만 검사해요. 문서의 "CI" 표현은 "로컬 검사"로 고치도록 chat에 요청해요설정이 늘지 않아요. 대신 검사를 건너뛴 변경을 막을 장치가 없어요

A를 고르면 다음 단계 시작 전에 워크플로를 추가하고, GRAPHICS 8장 문구는 그대로 둬요. chat에는 같은 내용을 handoff로 알렸어요(docs/handoff/to-chat/2026-10-01-step12a-done.md).

2. 이제 되는 것

  • 캐릭터 그림: 외형마다 레이어 시트를 정해진 순서로 겹치고, 키 색을 고른 색으로 바꿔 한 번만 합성해요. 같은 외형은 여러 사람이 함께 써요. 합성이 끝나기 전에는 지금까지 보던 색 도형으로 그려요.
  • 걷기 동작: 움직이는 동안 왼발→서기→오른발→서기를 75ms마다 바꿔요. 멈추면 서기, 자리비움은 서기 + 반투명이에요. 방향은 내 캐릭터는 예측 방향, 다른 사람은 서버 방향을 따라요.
  • 닉네임: 말풍선과 같은 픽셀 폰트(PixelKo)로 머리 위에 떠요. 화면 밖 캐릭터의 닉네임은 만들지 않아요. 아래쪽 캐릭터의 닉네임이 위에 겹쳐요.
  • 옷장: 툴바 "옷장" 버튼이나 내 프로필 카드의 "옷장"으로 열어요. 선택지는 서버가 허용한 목록 중 그림·색이 있는 것만 보여요. 저장하면 같은 계정의 다른 탭과 주변 사람 화면에서도 바뀌어요. 서버가 거절하면 그 이유를 해당 선택지 옆에 보여 줘요.
  • 자산 도구: pnpm art:placeholders는 자리표시 시트 53장을, pnpm art:templates는 제작 템플릿 3장(가이드·키 색 견본·기준 몸)을 만들어요. pnpm check:assets는 GRAPHICS 8장 캐릭터 레이어 규칙을 자동으로 검사해요(크기, 투명도, 색, 여백, 발 위치, 좌우 반전 금지, 카탈로그 일치, 파일 크기·메타데이터).

12a E2E(e2e/phase3-avatar.spec.ts)는 네 가지를 확인해요.

  • 옷장에서 상의 색을 바꿔 저장하면 내 캐릭터 픽셀 색이 바뀌어요. 같은 계정의 다른 탭에서도 바뀌고, 그 탭의 옷장도 새 외형에서 시작해요.
  • 모달은 캔버스 영역 안에 들어와요. 키보드로 아래 선택지까지 가도 페이지가 밀리지 않아요(1280×800, 390×844).
  • 닉네임 DOM의 위치·높이, 말풍선 꼬리 끝이 닉네임 바로 위에 오는지, 겹침 순서를 확인해요.
  • rAF 간격 p95 ≤ 20ms

검증이 실제로 잡는지도 확인했어요. 외형이 바뀔 때 합성 그림을 다시 요청하는 코드를 일부러 빼면 픽셀 검사가 실패해요(#63c74d 그대로). 아래 4-1의 수정을 빼면 페이지 밀림 검사가 실패해요(scrollTop 210).

4. 진행 중 발견해서 고친 것

문제처리
4-1. 옷장에서 키보드로 아래 선택지로 가면 화면 전체가 210px 위로 밀림. 데스크톱 스크린샷이 잘린 것을 보고 원인을 재 봤어요. 시각적으로 숨긴 라디오 버튼의 기준 상자가 선택지 스크롤 영역 밖(배경)이었어요. 그래서 포커스를 옮기면 선택지 대신 페이지가 스크롤됐어요버튼 라벨을 기준 상자로 지정해 수정. 1280×800·390×844에서 키보드로 고른 뒤 페이지가 밀리지 않는지 E2E에 추가(수정을 빼면 실패 확인)
4-2. 모바일에서 옷장 모달이 캔버스 영역보다 길어져 저장 버튼이 잘림배경을 flex로 바꿔 모달 높이를 캔버스 영역에 맞추고 선택지만 스크롤. "저장이 화면 안에 보임"을 E2E로 확인
4-3. 처음 쓴 E2E는 "합성 완료"를 확인한다고 했지만, 고른 기준 픽셀(상의 가운데 색)은 합성 전 대체 그림과 색이 같았음합성 그림에만 있는 밝은 줄(hi) 픽셀로 바꿔 합성 여부를 구분
4-4. 자리표시 생성기가 머리 4종의 왼쪽·오른쪽을 단순 반전으로 그림. check:assets의 미러 금지 규칙이 잡음옆모습에서 뒤통수 쪽이 남도록 좌우를 다르게 그려 수정
4-5. 걷기 동작이 프레임이 띄엄띄엄 오면 매번 처음부터 다시 시작함(단위 테스트에서 발견)"멈춘 시각" 기준으로 바꿔 75ms 이하 정지에서는 주기를 이어가게 수정
4-6. 캐릭터를 화면 왼쪽·위쪽 밖으로만 걸러 내고 오른쪽·아래쪽 밖은 그리고 있었음네 방향 모두 걸러 냄(닉네임 노드도 화면 안 캐릭터만)

5. 남은 것과 한계

  • 자리표시 그림은 단순 도형이라 일부 아이템이 잘 안 보여요(예: 앞모습에서 포니테일 뒷머리는 몸에 가려요). 12b에서 실제 그림으로 바뀌어요.
  • 내 캐릭터를 표시하는 흰 테두리(5단계부터 쓰던 것)는 그대로 뒀어요. 실제 그림에서 다른 표시를 원하면 GRAPHICS에서 정해야 해요(chat에 알림).
  • 색 이름(예: "숲색", "먹색")은 제가 정한 화면 문구예요. 바꾸고 싶으면 알려 주세요.
  • 합성 그림 캐시는 외형 수만큼 늘어요(1장 약 61KB, 300명이 모두 달라도 약 18MB — GRAPHICS 2.9 추정과 같아요). 옷장에서 여러 조합을 눌러 보면 그만큼 더 쌓이고, 새로고침하면 비워져요.
  • rAF 측정은 헤드리스 Chromium 값이에요. 실제 저사양 기기와 Safari는 확인하지 않았어요.
