결론. ROADMAP 9단계를 완료했어요. 하단 패널에 그룹 탭이 생겼어요. 그룹을 만들고, 멤버 전원에게 메시지를 보내고, 안 읽음을 확인할 수 있어요. 방장은 멤버를 초대·강퇴하고 이름을 바꾸거나 해산할 수 있고, 누구나 나갈 수 있어요. 작업 중에 chat이 계약 결정 4건을 문서에 반영해 인박스로 보냈고, 그에 맞춰 Mock도 고쳤어요. 검증 결과는 단위 테스트 306건, domain 커버리지 100%, E2E 20건(두 번 연속 통과)이에요.

2. 이제 되는 것

  • 만들기: 이름 2~20자. 앞뒤 공백은 빼고, 길이는 요청 전에 먼저 확인해요. 만들면 목록 맨 위에 생기고 바로 대화가 열려요.
  • 대화: 위치와 상관없이 멤버 전원에게 전달돼요. 위로 스크롤하면 이전 메시지를 50개씩 불러와요. 전송이 실패하면 "다시 보내기"로 재시도할 수 있어요. 나간 사람이 보냈던 메시지도 닉네임이 보여요.
  • 안 읽음: 다른 탭에 있을 때 그룹 메시지가 오면 그룹 탭 배지와 해당 그룹 줄에 숫자가 올라가요. 대화를 열면 읽음 처리돼요. 내가 보낸 메시지는 안 읽음에 세지 않아요(이번에 계약으로 확정).
  • 방장: 초대(인원이 가득 차면 입력이 막히고 서버의 GROUP_FULL도 안내), 강퇴, 이름 변경, 해산(한 번 더 확인).
  • 멤버: 나가기(한 번 더 확인). 방장이 나가면 가장 오래된 멤버가 방장을 이어받아요(서버 규칙).
  • 초대받음·강퇴됨: 다른 사람이 나를 초대하면 목록에 바로 나타나요. 강퇴되거나 해산되면 목록에서 빠지고 안내가 떠요.
  • Mock: 브라우저 콘솔에서 __devpleMock.groupFrom('g_01', 'u_01', '안녕'), inviteMe('새 모임'), kickMe('g_02'), seedGroup('g_01', 60)로 흉내 낼 수 있어요(README). 내가 그룹에 보내면 가짜 멤버가 5초 뒤 답해요.

9단계 E2E (e2e/phase2-group.spec.ts)는 여섯 가지를 확인해요.

  • 만들기 → 전송(말풍선 없음) → 다른 탭에 있을 때 받은 멤버 메시지 → 안 읽음 → 열면 읽음
  • 방장 초대 → 강퇴 → 이름 변경 → 해산
  • 멤버로서 나가기
  • 강퇴되면 스레드가 닫히고 안내, 초대받으면 목록에 표시
  • 62개 무한 스크롤
  • 모바일 헤더 한 줄

4. 인박스 처리 (chat 결정 반영)

  • API_CONTRACT 1.6: 그룹 메시지를 보내면 서버가 보낸 사람의 읽음 위치를 그 메시지로 옮겨요(제 제안이 채택됨). GET /groups는 최근 활동 먼저, GET /dm은 updatedAt 내림차순으로 정렬돼요.
  • DOMAIN 1.5: DM 안 읽음은 "상대가 보낸 메시지 중 readAt이 없는 것"으로 정의됐어요. 이에 맞춰 Mock이 따로 들고 있던 안 읽음 카운터를 없애고, 매번 메시지에서 계산하게 바꿨어요. 카운터를 거치지 않는 경로(과거 메시지 시드)에서 숫자가 어긋날 수 있었거든요.
  • GRAPHICS 1.3: 말풍선 가장자리 규칙(B안)과 DM 말풍선 색 #2ce8f5가 기록됐어요. PRD 1.4: 내가 보낸 DM의 말풍선 규칙이 기록됐어요.
  • 말풍선끼리 겹치는 문제는 12단계 플레이 테스트 때까지 현재 방식을 유지하기로 했어요.

6. 남은 것과 한계

  • 방장이 나갈 때 방장이 넘어가는 경로는 Mock과 단위 규칙만 있고 E2E는 없어요. Mock에서는 나 말고 다른 멤버가 전부 가짜라, 다른 사람이 받는 화면(초대된 사람의 group.joined 등)은 확인할 수 없어요.
  • 방장 화면에서 멤버가 많으면 이름 변경·해산 버튼까지 스크롤해야 해요(데스크톱 패널 최대 280px).
  • 재접속 뒤 그룹 목록을 다시 맞추는 동작(sync.required)은 10단계예요.
  • E2E는 Chromium에서만 돌려요(Safari 미검증).
