2. 이제 되는 것

  • 그림의 원본은 텍스트예요 (art/source/): 아바타는 .pix로 방향마다 서기 1장만 그리고, 걷기 프레임은 빌드가 만들어요(머리·몸통 1px 흔들림, 캐릭터 자신의 발을 교대로 듦). 타일은 .tiles예요. pnpm art:build가 PNG를 만들고 바로 검수해요. PNG만 고치면 CI가 막아요.
  • AI 제작 키트 (art/ai/): 안내서, 아이템별 지시문 43개(영어 프롬프트·키 색·팔레트 hex 포함), 생성 이미지를 격자에 맞추고 허용 색으로 바꿔 .pix로 만드는 art:ingest. 개발용 그림 43종을 4배로 키워 넣어도 원본과 똑같이 돌아오는지 자동으로 확인해요.
  • 개발용 그림: 기준 몸 + 아이템 42종(뒤쪽 시트 9개), 4방향을 각각 그렸어요(좌우 반전 없음). 타일셋 main(벽·연못·화단 9분할 세트 포함).
  • 맵 레이어: 바닥 → 물건 → 캐릭터 → 위층 순으로 그려요. 타일셋을 못 읽으면 예전처럼 색으로 칠한 바닥으로 열어요.

5. 진행 중 발견해서 고친 것

문제처리
5-1. 걷기 파생이 모든 방향에서 화면 왼쪽 다리를 먼저 들었어요. GRAPHICS 2.2가 "캐릭터 자신의 왼발"로 정해서 아래 방향만 반대였어요방향별 규칙으로 고치고 시트 53장을 다시 만들었어요(단위 테스트 추가)
5-2. 운영 이미지를 브라우저로 열어 보니 CSP 위반 1건(zod의 eval 시험)이 있었어요zod jitless로 해결 → 위반 0
5-3. 테스트에 넣은 보이지 않는 문자(ZWJ 등)가 도구 입력을 거치며 실제 문자로 저장됐어요(11b 때와 같은 문제)이스케이프·String.fromCodePoint로 바꾸고 전체를 검사했어요
5-4. 나무 잎 E2E가 처음에 화면 밖 나무를 골라 빈 픽셀을 읽었어요카메라 안에 들어오는 나무로 바꾸고, 타일이 그려질 때까지 기다리게 했어요(3회 반복 통과)

6. 남은 것과 한계

  • 개발용 그림은 단순해요. 손 소품이 작아 잘 안 보이고, 옆모습 걷기는 다리 절반만 들려요. 최종 그림(12c)에서 바뀌어요.
  • 타일셋은 지금 맵에 필요한 것만 그렸어요(GRAPHICS 3.2의 의자·책장·램프·게시판 등은 아직 없음). 맵 편집은 아직 JSON 직접 편집이에요.
  • GRAPHICS 7.2 표에 지운 명령(art:placeholders)이 남아 있어서 chat에 삭제를 요청했어요.
  • 맵 main.json(계약 자산)에 레이어가 생겨서 서버에 알렸어요. 충돌·스폰은 그대로라 서버 코드 변경은 필요 없어요.
