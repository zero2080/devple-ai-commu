> 문서 버전: 2.2 (2026-10-01, 최종 그림은 AI 키트로 · 걷기 프레임 파생 · 12b/12c)
> 상태: 확정 (색 램프 hex 값은 12c 최종 그림과 함께 `palette.json`에서 최종 고정)

## 1. 공통 규격

| 항목 | 값 | 비고 |

| 스타일 | 90년대 16비트 콘솔풍 도트 아트 (SNES·GBA 시대), 3/4 탑다운 시점 | 등각(isometric) 아님 |

| 원본 해상도 | **1x** (확대하지 않은 원본 픽셀) | 렌더 시 정수 배율(2x 기본)로 확대. 2x로 그린 원본은 받지 않음 |

| 안티앨리어싱 | **없음.** 모든 픽셀은 허용된 색 그대로 | 반투명 픽셀 금지 (알파는 0 또는 255) |
| 외곽선 | 1px, 고정색 `#181425` | 캐릭터·오브젝트 공통. 바닥 타일은 외곽선 없음. 외곽선은 팔레트 스왑 대상이 아니다 |
| 디더링 | 최소한만 (그라데이션 대용으로 남용 금지) | |

### 1.1 팔레트
- 프로젝트 전체 **단일 마스터 팔레트, 32색 이내**. 파일: `src/assets/palette.json`
- 시작 팔레트로 **Endesga 32** (제작자 ENDESGA, Lospec 배포)를 채택하고, **12c(최종 그림) 때** 색을 교체·확정한다 (12b 개발용 그림은 초안 램프로 그린다). 확정 후에는 변경 시 모든 자산을 재검수한다
  - 사용 조건 (2026-09-30 확인): Lospec 팔레트 페이지에 명시된 라이선스 문구는 없음. 무료 다운로드로 배포되고 상업 에셋 팩에도 널리 쓰이며, 커뮤니티 표기는 "사이트 팔레트는 자유 사용, 원작자 크레딧은 선택" 수준 (정확도 중간 — 공식 라이선스 아님, 법적 판단 아님)
  - 따라서 `src/assets/LICENSES.md`에 출처와 원작자 **크레딧을 항상 표기**한다 ("Palette: Endesga 32 by ENDESGA, lospec.com/palette-list/endesga-32"). 색을 대부분 교체해 원형이 남지 않으면 "Endesga 32 기반"으로 표기 유지
- 순수 검정 `#000000`·순수 흰색 `#ffffff`는 외곽선으로 쓰지 않는다. 예외: 코드가 그리는 UI 요소
- 캐릭터 레이어는 마스터 팔레트 색 대신 **키 색**(2.7)으로 칠하는 부분이 있다. 키 색은 마스터 팔레트에 없는 색이며, 화면에는 절대 그대로 나타나지 않는다

```ts
// src/assets/palette.json
interface PaletteFile {
  name: string;                      // 'devple-32'
  colors: string[];                  // 마스터 32색 hex
  ramps: Record<string, ColorRamp>;  // rampId → 램프 (2.7)
  rampGroups: { skin: string[]; hair: string[]; item: string[] };  // 선택지 순서
}
interface ColorRamp { hi: string; base: string; shadow: string }   // 모두 colors 안의 값
```

### 1.2 렌더 전제 (코드 쪽 보장)
- `ctx.imageSmoothingEnabled = false`, `image-rendering: pixelated`
- 모든 그리기 좌표는 정수 픽셀. 서브픽셀 위치 금지
- 줌은 2x·3x·4x만 (1x 렌더 없음 — 모바일도 2x)
- 뷰포트 보장 영역 (캔버스 CSS 크기 기준, 기본 줌 2x):

| 환경 | 판정 | 보장 영역 | 근거 |
|---|---|---|---|
| 데스크톱 | 캔버스 폭 ≥ 640 CSS px | **20×15 타일** (640×480) | 맵 탐색에 충분한 시야 |
| 모바일 | 캔버스 폭 < 640 CSS px | **근접 범위 정사각형** `(2 × proximityRadius + 1)` 타일 (반경 5 → 11×11 = 352×352) | 내 말이 닿는 상대는 항상 화면에 보인다 |

- 모바일 보장에 필요한 최소 캔버스 크기는 352×352 CSS px (반경 5 기준). 지원 하한 기기 폭 **360 CSS px** (현행 주류 스마트폰 세로 폭은 대체로 360~430 — 정확도 중간). 폭 360 미만은 보장하지 않는다
- 보장 영역보다 캔버스가 크면 더 넓게 보여준다 (상한 없음, 맵 경계 클램프만). 보장 영역을 만족시키려고 줌을 낮추지 않는다 — 레이아웃(패널 배치)이 캔버스 크기를 확보한다
- `proximityRadius`는 서버 값이므로 모바일 보장 영역도 런타임에 계산한다. 반경이 커져 보장 영역이 캔버스를 넘으면 보장을 포기하고 카메라 중심만 유지 (반경은 운영 테스트 후 조정 대상, PRD 9)

## 2. 캐릭터 아바타 — 레이어 합성 + 팔레트 스왑

캐릭터는 한 장의 완성 그림이 아니다. **몸(body) 1장 위에 슬롯별 아이템 시트를 겹쳐 그리고**, 각 시트의 **키 색을 사용자가 고른 색 램프로 치환**해 완성한다 (레트로 게임의 paper-doll + palette swap 기법).

```
 body ──┐
 bottom ┤
 shoes  ┤  같은 프레임 규격(24×40, 4방향×4프레임)의 시트들을
 top    ├─ 2.6 순서로 겹치고, 키 색(2.7)을 사용자 색으로 치환 → 합성 시트 1장
 hair   ┤
 face   ┤
 hat    ┤
 hand ──┘
```

### 2.1 프레임
| 항목 | 값 |
|---|---|
| 프레임 크기 | **24×40 px** |
| 앵커 | 프레임 하단 중앙 `(12, 40)` = 캐릭터가 서 있는 타일의 바닥 중앙 |
| 몸 박스 | `x 4–19, y 8–39` (16×32 = 가로 1타일 × 세로 2타일). 캐릭터의 기본 실루엣은 이 안에 든다 |
| 위쪽 여백 | `y 0–7` (8px) — **모자 전용** |
| 좌우 여백 | `x 0–3`, `x 20–23` (각 4px) — 손 소품·머리숱·모자 챙 전용 |
| 방향 | 4방향 `down` `left` `right` `up` — **4방향 모두 별도 제작** (좌우 미러 금지: 소품을 드는 손·가르마 등 비대칭 때문) |

- 타일 점유는 여전히 1칸이다. 여백은 **그림만** 옆·위 타일로 삐져나가는 영역이다
- 클릭·탭 판정은 프레임 전체가 아니라 **몸 박스**로 한다 (옆 사람 소품을 눌러 엉뚱한 프로필이 열리지 않도록)

### 2.2 2등신 체형 가이드 (down 방향 기준, 프레임 좌표)
| 부위 | 영역 | 비고 |
|---|---|---|
| 머리 | `y 8–23` (16px), 폭 약 14px (`x 5–18`) | 머리 = 몸 전체의 절반 → 2등신 |
| 눈 | `y 16–17` 부근, 2px 높이 | 몸 레이어에 고정색으로 그림 |
| 몸통 | `y 24–31`, 폭 10~12px | 팔 포함 |
| 다리·발 | `y 32–39`, 발바닥 = `y 39` | 발 아래 끝이 앵커. 걷기에서 들어 올린 발만 `y 38` (2.3) |

- 모든 아이템은 이 체형에 맞춰 그린다. 체형 변형(키·체격)은 제공하지 않는다
- 기준 체형은 `body_base` 시트가 원본이다. 가이드 이미지는 7.2의 템플릿으로 제공

### 2.3 애니메이션
| 항목 | 값 |
|---|---|
| 프레임 | 방향별 4프레임: `0` 서기(idle), `1` 왼발, `2` 서기(중간), `3` 오른발. 왼발·오른발은 **캐릭터 자신의** 발 (`down`에서 왼발은 화면 오른쪽) |
| 걷기 재생 | `1 → 2 → 3 → 0` 순환, 프레임당 **75ms** (타일당 150ms 이동 = 2프레임/타일) |
| 프레임 1·3 규칙 | `y 0–31`(모자 여백·머리·몸통)을 **1px 아래로**. 다리 `y 32–39`는 제자리에 두고, 프레임 1은 왼발·프레임 3은 오른발을 **1px 들어 올린다**(발바닥 `y 38`). 디딘 발은 `y 39`. 모든 레이어가 같은 규칙을 따라야 겹쳤을 때 어긋나지 않는다 |
| 프레임 2 | 프레임 0과 같다 |
| **제작 방식** | **방향마다 서기(0) 1장만 그린다** (4방향 = 4장). 프레임 1–3은 위 규칙으로 코드가 만든다 (`.pix` 원본 → `pnpm art:build`). 원본에 프레임을 직접 그린 블록이 있으면 파생보다 우선한다. 다리를 왼쪽·오른쪽으로 나누는 열 범위는 방향별로 `body_base`와 빌드 규칙이 정한다 (Claude Code 제안 A 채택 — 생성 AI가 가장 약한 프레임 간 일관성 문제를 피한다) |
| 자리비움 | 별도 프레임 없음. 코드가 합성 결과의 idle 프레임에 알파 0.5 적용 |

### 2.4 시트 배치
레이어 1장 = PNG **96×160 px** (4열 × 4행). 행 = 방향, 열 = 프레임. **모든 레이어가 같은 배치**다.

```
        col0     col1     col2     col3
row0    down/0   down/1   down/2   down/3
row1    left/0   left/1   left/2   left/3
row2    right/0  right/1  right/2  right/3
row3    up/0     up/1     up/2     up/3
```
프레임 `(dir, frame)`의 좌상단 = `(frame * 24, rowOf(dir) * 40)`
- 아이템이 보이지 않는 프레임은 완전 투명으로 둔다 (예: 뒤돌았을 때 안 보이는 안경)

### 2.5 슬롯
| 슬롯 | 키 | 필수 | 내용 | 색 채널 |
|---|---|---|---|---|
| (몸) | `body` | — (고정 1종) | 피부·눈·입. 사용자는 피부색만 고른다 | `skin` |
| 머리모양 | `hair` | 선택 (없음 = 민머리) | 앞머리·뒷머리 | `hair` (+ `secondary`: 리본 등) |
| 모자 | `hat` | 선택 | 모자·머리띠·헬멧 | `primary`, `secondary` |
| 얼굴 액세서리 | `face` | 선택 | 안경·마스크·수염 | `primary`, `secondary` |
| 상의 | `top` | **필수** | 셔츠·후드·원피스 | `primary`, `secondary` |
| 하의 | `bottom` | **필수** | 바지·치마 | `primary`, `secondary` |
| 신발 | `shoes` | **필수** | 신발·부츠 | `primary`, `secondary` |
| 손 소품 | `hand` | 선택 | 캐릭터 **오른손**에 드는 물건 (꽃·풍선·책) | `primary`, `secondary` |

- `top`이 `coversBottom: true`(원피스·로브)이면 `bottom` 레이어를 그리지 않는다. 이때도 `bottom` 값은 데이터상 유지 (벗으면 다시 보이도록)
- 모자가 머리카락을 가리는 처리(마스킹)는 하지 않는다. 모자는 머리카락 위에 그려지므로 **모자 디자인이 정수리를 충분히 덮도록** 그린다 (한계: 부피 큰 머리는 모자 옆으로 삐져나올 수 있음 — 12c 최종 그림 후 재검토)

### 2.6 레이어 순서와 front / back 시트
아이템은 `front` 시트(필수)와 `back` 시트(선택) 두 장으로 나뉠 수 있다. `back`은 **몸보다 뒤에** 그려질 부분이다.

그리기 순서 (위에서 아래로 먼저 → 나중):
| 순서 | 레이어 |
|---|---|
| 1 | `hair.back` |
| 2 | `hat.back` |
| 3 | `hand.back` |
| 4 | `body` |
| 5 | `bottom` (`top.coversBottom`이면 생략) |
| 6 | `shoes` |
| 7 | `top` |
| 8 | `hair.front` |
| 9 | `face` |
| 10 | `hat.front` |
| 11 | `hand.front` |

- 순서는 방향과 무관하게 고정이다. 방향에 따라 앞뒤가 바뀌는 부분은 **프레임별로 front/back 중 어느 시트에 그릴지**로 해결한다
- 손 소품 (오른손):

| 방향 | 오른손 위치 | 소품을 그릴 시트 |
|---|---|---|
| `down` | 화면 왼쪽 | `front` |
| `right` | 몸 앞쪽 (가까운 손) | `front` |
| `left` | 몸 뒤쪽 (먼 손) | `back` |
| `up` | 화면 오른쪽, 몸 앞에 들어 가려짐 | `back` (어깨 위로 보이는 부분만 `front`) |

- 긴 머리: `down`·`left`·`right`에서 등 뒤로 넘어가는 부분은 `hair.back`, `up`에서는 뒷머리 전체가 보이므로 `hair.front`

### 2.7 색 커스터마이징 — 키 색과 램프
레이어의 "색이 바뀌는 부분"은 아래 **키 색**으로만 칠한다. 각 채널은 3단 명암(밝음 `hi` · 기본 `base` · 어둠 `shadow`)이다.

| 채널 | hi | base | shadow | 쓸 수 있는 레이어 |
|---|---|---|---|---|
| `skin` | `#ffff80` | `#ffff00` | `#808000` | `body`만 |
| `hair` | `#8080ff` | `#0000ff` | `#000080` | `hair`만 |
| `primary` | `#ff8080` | `#ff0000` | `#800000` | `hair` 외 모든 아이템 |
| `secondary` | `#80ff80` | `#00ff00` | `#008000` | 모든 아이템 (`hair` 포함) |

- 키 색은 순수 RGB 원색 계열이라 사람이 알아보기 쉽고, 마스터 팔레트(Endesga 32)에 없는 값이라 혼동이 없다
- 키 색이 아닌 부분(외곽선, 눈, 금속 장식 등)은 **마스터 팔레트 색**으로 칠하며 치환되지 않는다. 레이어당 고정색은 외곽선 제외 **4색 이내**
- 합성 시 코드는 키 색 픽셀을 정확히 일치(RGB 완전 일치, 알파 255)로 찾아 사용자가 고른 램프의 같은 단계 색으로 바꾼다
- 사용자는 **프리셋 램프 중에서만** 고른다 (자유 색상 없음). 램프는 모두 마스터 팔레트 색으로 구성되므로 합성 결과는 항상 32색 안에 있다

### 2.8 카탈로그 (`catalog.json`)
아이템의 그림과 메타데이터 목록. 파일: `src/assets/sprites/avatar/catalog.json`

```ts
type SlotId = 'hair' | 'hat' | 'face' | 'top' | 'bottom' | 'shoes' | 'hand';

interface AvatarCatalog {
  body: { front: string };                 // body_base.png
  items: CatalogItem[];
}
interface CatalogItem {
  id: string;                              // '<slot>_<name>', 소문자 snake. 예: 'hat_beanie'
  slot: SlotId;                            // id 접두사와 반드시 일치
  name: string;                            // 선택 UI 표시명 (한국어)
  sheets: { front: string; back?: string };
  channels: ('primary' | 'secondary')[];   // 시트에 실제로 쓴 키 채널 (hair의 'hair' 채널은 암묵)
  defaultColors: { primary?: string; secondary?: string };  // 사용자가 고르지 않았을 때 rampId
  coversBottom?: true;                     // top 전용
}
```
- **아이템 ID 접두사 = 슬롯**이다. 서버는 카탈로그 파일 없이 ID만으로 슬롯 일치를 검증한다
- 목록 원천은 서버다 (`ServerConfig.avatarOptions.itemIds`). 새 아이템은 **그림(catalog) 먼저 배포 → 서버 목록 추가** 순서. 반대 순서면 그림 없는 아이템이 노출된다
- 서버 목록에 있는데 카탈로그에 없는 ID가 오면: 렌더는 그 슬롯을 비운다(필수 슬롯이면 카탈로그의 해당 슬롯 첫 아이템) + `console.warn`. 선택 UI에서는 빠진다

### 2.9 합성과 캐시 (코드 쪽 규칙)
- 외형(`Appearance`, DOMAIN 3.7)이 정해지면 **오프스크린 캔버스에 96×160 합성 시트를 1회 만든다**: 2.6 순서로 레이어를 겹치고 2.7 규칙으로 키 색을 치환
- 매 프레임에는 합성 시트에서 프레임만 잘라 그린다. 매 프레임 합성·치환 금지 (60fps 유지)
- 캐시 키 = 정규화한 Appearance의 해시. 같은 외형은 사용자끼리 공유. 합성 시트 1장 ≈ 61 KB (96×160×4) — 300명 전원이 달라도 약 18 MB (정확도 중간, 브라우저 메모리 기준 허용 범위로 판단)
- 채널이 비어 있으면(예: 사용자가 `secondary`를 안 고름) 아이템의 `defaultColors`, 그것도 없으면 램프 그룹의 첫 램프
- 미리보기(선택 UI·프로필 카드): 합성 시트의 `down/0`을 3x로 표시. 채팅 로그 아이콘이 필요하면 머리 영역 `x 4–19, y 8–23`을 잘라 쓴다

## 3. 타일셋

### 3.1 규격
| 항목 | 값 |
|---|---|
| 타일 크기 | 16×16 px |
| 시트 크기 | **256×256 px** = 16열 × 16행 = 256타일 (시트 1장/맵) |
| 인덱스 | `index = row * 16 + col`, 0부터. `-1` = 빈칸 |
| 여백·간격 | 없음 (타일이 빈틈없이 배치). 코드가 정수 좌표만 쓰므로 번짐 없음 |
| 파일 | `src/assets/tilesets/<tilesetId>.png` + `<tilesetId>.tileset.json` |

### 3.2 필수 타일 (맵 `main` 기준)
| 구역 | 내용 | 수량 |
|---|---|---|
| 바닥 | 잔디·흙·돌바닥·나무바닥 각 2~3변형 (단조로움 방지) | ~12 |
| 벽 | 9분할(상·하·좌·우·4모서리·내부) + 내부 모서리 4 | 13 |
| 문·창 | 열린 문, 창문 (장식) | ~4 |
| 가구·소품 | 테이블, 의자(4방향), 책장, 화분, 카펫(9분할), 램프, 게시판 | ~30 |
| 야외 | 나무(2×2, 위쪽은 `above` 레이어), 울타리, 바위, 꽃 | ~16 |
| 여유 | 향후 확장 | 나머지 |

- 2타일 이상 크기 오브젝트(나무·책장)는 **타일 단위로 분할**해 시트에 넣고 맵에서 조합한다. 캐릭터보다 위에 그려야 할 부분(나무 꼭대기, 지붕)은 `above` 레이어에 배치
- 벽·카펫 같은 9분할 세트는 시트에서 **3×3 블록으로 인접 배치** (맵 에디터 자동 타일 대응 여지)
- 타일셋은 마스터 팔레트 전체를 쓸 수 있고 키 색은 쓰지 않는다

### 3.3 tileset JSON
```ts
interface TilesetData {
  id: string;
  image: string;               // PNG 경로
  tileSize: 16;
  columns: 16;
  count: number;               // 실제 사용 타일 수 (≤ 256)
  names?: Record<number, string>;  // index → 사람이 읽는 이름 (디버그·에디터용, 선택)
}
```

## 4. 맵

- `MapData` 정의는 DOMAIN 4.3. 이 문서는 자산 관점의 규칙만 추가한다
- `tileset` 필드로 3장의 타일셋 ID를 참조 (맵당 1개)
- 레이어 구성 (그리기 순서):

| name | order | 내용 | 비고 |
|---|---|---|---|
| `floor` | below | 바닥. 모든 타일이 채워짐 (`-1` 없음) | |
| `objects` | below | 가구·벽·나무 밑동 등 캐릭터와 같은 높이 | 정적. y 정렬 없이 캐릭터 아래 |
| `overhead` | above | 나무 꼭대기·지붕·처마 | 캐릭터 위 |

- `collision`은 레이어와 독립. 벽·가구·나무 밑동 타일은 1, 카펫·문·꽃은 0
- 맵 `main`: **40×30 타일** (640×480 px), `spawn: {20, 15}`. 스폰 주변 5×5는 항상 통행 가능
- 맵 그림은 **레이어별 PNG로 미리 그려 오지 않는다.** 타일셋 + 인덱스 배열이 원본이며, 완성 이미지가 필요하면 코드가 렌더한다
- 맵 편집: 당장은 JSON 직접 편집. 타일 수가 늘면 Tiled(무료 맵 에디터)의 JSON 내보내기 → `MapData` 변환 스크립트 도입 검토 (12b 이후)

## 5. 말풍선 · 닉네임 · UI

말풍선과 닉네임은 **DOM 오버레이**(ARCHITECTURE 2.3)라 이미지 자산이 아닌 CSS 스펙이다.

### 5.1 폰트
- 채택 (사용자 결정 2026-09-30): **Galmuri11 서브셋을 `PixelKo`로 이름을 바꿔 동봉**. `src/assets/fonts/PixelKo.woff2` + 원본 라이선스 `OFL-Galmuri.txt`
  - 라이선스: SIL OFL 1.1. 서브셋은 수정본이므로 Reserved Font Name "Galmuri"를 폰트 이름(name ID 1/3/4/6/16)에 쓰지 않는다
  - 수록 범위: 한글 완성형 11,172자, ASCII 95자, **한글 호환 자모 U+3131–U+318E**(ㅋㅋ·ㅠㅠ 등 채팅에서 흔함), 일반 문장부호(`…` `·` `「」` 등). 자모·문장부호는 원본에 있는 글리프에 한정
  - 파일 상한 **256 kB** (woff2)
  - 빌드 `scripts/fonts/build-pixelko.sh`, 검사 `scripts/fonts/check-font.py`
- 크기: **em × 줌**만 사용. PixelKo em = 12px → 2x 24px, 3x 36px, 4x 48px. CSS 변수 `--pixel-font-em: 12px`, `line-height: 1`. 다른 크기·비정수 배율 금지
- 픽셀 폰트에 없는 문자(이모지·한자 등)는 시스템 폰트 폴백. `font-family: 'PixelKo', system-ui`
- `LICENSES.md` 항목 형식: 이름 / 원작자 / 라이선스 / 원본 URL / 수정 내용(서브셋 범위, 이름 변경)

### 5.2 말풍선 (`SpeechBubble`)
| 항목 | 공개 | DM |
|---|---|---|
| 배경 | 팔레트 밝은 회백색 | 팔레트 밝은 청록(cyan) |
| 테두리 | 2px(1x 기준 1px × 줌) 어두운 외곽선, 모서리 1px 깎음 | 동일 |
| 꼬리 | 하단 중앙, 닉네임 블록 위를 가리킴 (아래 수직 배치) | 동일 |
| 최대 폭 | 12타일(192px × 줌). 초과 시 줄바꿈 | 동일 |
| 링크 버튼 | 하단, `↗ hostname`, 같은 폰트 | 동일 |

- 테두리는 CSS `box-shadow` 다중 그림자로 픽셀 외곽선을 그린다 (`border-image` 대신, 줌마다 정수 px)
- **수직 배치** — 말풍선은 닉네임 **위에 쌓는다** (Claude Code 제안 A 채택). 월드 px 기준, 모두 × 줌. `top` = 캐릭터 **프레임 상단** = 앵커 y − 40 (2.1. 모자 여백까지 포함하므로 모자를 바꿔도 닉네임 위치가 움직이지 않는다)

| 요소 | 위치 |
|---|---|
| 닉네임 블록 | 하단 = `top − 2`, 높이 = 닉네임 line-height (PixelKo em 12) |
| 말풍선 꼬리 끝 | 닉네임 블록 상단 − 1 |
| 말풍선 본문 하단 | 꼬리 끝 − 꼬리 높이 3 |

  - PixelKo 적용 시(12a부터 현재): 꼬리 끝 = `top − 15`, 본문 하단 = `top − 18`
  - 말풍선이 떠 있어도 닉네임은 **항상 표시** (예외: 아래 가장자리 규칙으로 말풍선이 내려와 가리는 경우)
- **화면 가장자리** (사용자 결정 B, 2026-09-30)
  - 위쪽: 말풍선이 캔버스 상단을 넘으면 본문을 캔버스 상단(y = 0)까지 내린다. 내려온 동안에는 발화자의 닉네임과 머리를 가릴 수 있다
  - 좌우: 넘치면 본문을 캔버스 안쪽으로 밀고, 꼬리는 계속 발화자를 가리킨다
  - 표시 여부는 말풍선이 아니라 **발화자 프레임**이 화면에 일부라도 보이는지로 판정한다
- **사용자당 말풍선 1개**: 같은 사용자의 새 메시지(공개·DM 무관)는 이전 말풍선을 대체하고 표시 시간을 새로 계산한다. 쌓아 올리지 않는다
- 겹침 순서: 말풍선끼리는 **최근 메시지가 위**. 닉네임끼리는 캐릭터 그리기 순서와 같이 **y가 큰 캐릭터가 위**. 닉네임 12자는 약 9타일 폭이라 인접 캐릭터 간 겹침은 정상 동작으로 본다
- 임시 색 (12c에서 `palette.json` 확정 전, Endesga 32 값): 공개 배경 `#c0cbdc`, DM 배경 `#2ce8f5` (`--bubble-dm-bg`), 글자·외곽선 `#181425`, 링크 버튼 `#ead4aa`. 공개·DM 공통으로 글자·외곽선·링크 버튼 색은 같다

### 5.3 닉네임
- 위치는 5.2 수직 배치 표 (블록 하단 = 프레임 상단 − 2px, × 줌), 가운데 정렬, 폰트 5.1
- 배경 없이 어두운 외곽선(`text-shadow` 4방향 1px × 줌)
- **DOM 오버레이** (12a에서 Canvas `fillText`에서 전환 완료 — 말풍선과 같은 레이어·폰트). 화면 밖 캐릭터의 노드는 만들지 않는다
- **내 캐릭터 표시**: 현재는 몸 박스의 흰 외곽선(5단계부터 유지). 12c 최종 그림 때 다시 정한다

### 5.4 UI 아이콘
- 로그인·패널·운영자 콘솔의 아이콘은 **16×16 단색 픽셀 아이콘** PNG 시트 `src/assets/ui/icons.png` (16열). 색은 CSS `mask-image`로 입힌다
- 필요 목록: 보내기, 닫기, DM, 그룹, 링크, 설정, 접속중, 자리비움, 경고, 검색, 옷장(외형 편집)

```
└── source/                      # `.pix` 텍스트 원본 — 시트는 여기서 `pnpm art:build`로 만든다
```
- 자산 로딩은 `game/assets/loader.ts` 한 곳에서 (CONVENTIONS 6장). 이미지 `<img>`·`new Image()`는 loader 밖에서 금지
- 모든 PNG는 커밋 전 `oxipng`(또는 동급) 무손실 압축. 파일당 상한 256 KB
- 자산 라이선스: 직접 제작 또는 CC0/OFL만. 출처·라이선스를 `src/assets/LICENSES.md`에 기록

## 7. 제작 지침 (이미지 생성 AI · 에이전트 · 사람)

### 7.1 제작 경로 (사용자 결정 2026-10-01: 최종 그림은 AI가 키트로 생성)
| 단계 | 그리는 쪽 | 비고 |
|---|---|---|
| 개발용 그림 (12b) | 코드(Claude)가 `.pix`로 직접 | 앱이 돌아가는 단순한 그림. 12c에서 교체된다 |
| 최종 그림 (12c) | 이미지 생성 AI가 키트(`art/ai/`)로 | 사용자가 생성 결과를 가져오면 아래 경로로 들여온다 |

최종 그림 경로:
1. `pnpm art:brief` → 아이템별 발주서 `art/ai/briefs/<id>.md` (7.3 공통 규칙 + 아이템별 내용)
2. AI가 **방향마다 서기 1장**을 생성 (걷기 프레임은 그리지 않는다 — 2.3)
3. `pnpm art:ingest` → 정수 배율 축소, 픽셀 격자 맞춤, **허용 키 색 + 마스터 팔레트로 양자화**, 알파 0/255 → `.pix` 원본
4. 정리는 `.pix` 텍스트 원본에서 한다 (에이전트·사람)
5. `pnpm art:build` → 걷기 프레임 파생 + 96×160 시트 + 8장 자동 검수. **통과한 시트만 커밋**

- 생성 AI는 정확한 픽셀 격자, 프레임 간 일관성, 지정한 hex 값을 지키지 못하는 경우가 많다 (정확도 높음). 그래서 (1) 서기 자세 4장만 받고 (2) 반드시 ingest로 양자화·격자 맞춤을 거치고 (3) 8장 검수를 통과해야 받는다. **이 경로를 거치지 않은 생성 이미지는 받지 않는다**
- 사람이 픽셀 에디터(Aseprite 등)로 그린 PNG도 같은 ingest 경로로 들여온다. 원본은 `.pix` 하나다
- 생성 결과가 실존 인물·기존 IP를 닮았으면 쓰지 않는다 (2.10). 사용한 생성 도구와 약관상 상업적 이용 가능 여부를 `LICENSES.md`에 기록한다 (도구마다 다름 — 사용 전에 확인)

### 7.2 템플릿·도구 (코드가 생성)
`art/templates/`에 다음을 둔다 (`pnpm art:templates`):
- `avatar-guide.png` — 96×160, 프레임 격자, 몸 박스·여백·체형 가이드선(2.1·2.2), 앵커 표시. 가이드 전용이며 시트에 포함하지 않는다
- `body_base.png` — 기준 몸. 12a는 코드가 만든 가짜 몸, 12b는 개발용 그림, 12c 최종 그림으로 교체하고 이후 모든 아이템의 기준
- `key-colors.png` — 2.7 키 색 12칸 견본 (스포이트용)

명령:
| 명령 | 용도 |
|---|---|
| `pnpm art:templates` | 위 템플릿 생성 |
| `pnpm art:placeholders` | 12a 임시 시트 생성 — **실제 그림이 들어온 뒤에는 실행 금지** (덮어씀) |
| `pnpm art:brief` | AI 발주서 생성 (`art/ai/briefs/<id>.md`) |
| `pnpm art:ingest` | 생성·외부 이미지 → `.pix` |
| `pnpm art:build` | `.pix` → 시트 + 검수 |
| `pnpm check:assets` | 8장 자동 검수 |

### 7.3 발주 공통 규칙
아이템별 발주서(`art/ai/briefs/<id>.md`)가 원본이다. 아래는 모든 발주서에 들어가는 공통 규칙이며, 발주서와 다르면 이 문서가 기준이다.
```
스타일: 1990년대 16비트 콘솔 RPG(SNES 시대) 도트 아트, 3/4 탑다운, 2등신 치비(머리 16px = 몸 16px).
해상도: 프레임 24×40px 기준. 결과물은 1배 또는 정수배(2배·4배)로, 픽셀이 격자에 딱 맞게.
기준: 첨부 avatar-guide.png의 몸 박스(x4–19, y8–39) 안에 몸이 들어가고, 발바닥은 y39. 위 8px은 모자, 좌우 4px은 소품·머리숱만.
자세: 방향마다 서 있는 자세 1장(아래·왼쪽·오른쪽·위 = 4장). 걷는 프레임은 그리지 않는다. 왼쪽·오른쪽은 각각 그린다(반전 재사용 금지).
레이어: 아이템 한 종만 그린다(몸 제외). 몸 뒤로 가야 할 부분은 별도 back 그림.
색: 바뀌는 부분은 키 색만 사용 — 주색 #ff8080/#ff0000/#800000, 보조색 #80ff80/#00ff00/#008000 (머리카락은 #8080ff/#0000ff/#000080). 그 외는 첨부 palette.json 색, 외곽선 #181425 1px.
금지: 안티앨리어싱, 반투명 픽셀, 그림자, 배경, 텍스트·로고, 실존 인물·기존 게임/애니 캐릭터 유사.
```

## 8. 검수 체크리스트

자산을 받을 때마다 확인한다. 하나라도 실패하면 반려. 캐릭터 레이어 항목은 `pnpm check:assets`(`scripts/check-assets.ts`)로 자동화되어 CI(`.github/workflows/ci.yml`)가 main 푸시·PR마다 돌린다 (12a, 사용자 결정). 폰트 검사는 Python fontTools가 필요해 CI 밖 수동 점검으로 둔다.

**캐릭터 레이어**
- [ ] 크기 정확히 96×160, 배율 1x
- [ ] 알파 값이 0 또는 255만 존재
- [ ] 사용 색 = 허용 키 색(2.7 표의 해당 레이어 행) ∪ 마스터 팔레트. 고정색은 외곽선 제외 4색 이내
- [ ] `body`는 `skin` 키만, `hair`는 `hair`·`secondary` 키만, 나머지 아이템은 `primary`·`secondary` 키만
- [ ] 카탈로그의 `channels`와 시트에 실제 쓰인 키 채널이 일치
- [ ] 모자 여백(`y 0–7`)에 픽셀이 있는 것은 `hat`뿐, 좌우 여백은 `hand`·`hair`·`hat`뿐
- [ ] `body`의 디딘 발 바닥이 모든 프레임에서 `y 39`(들어 올린 발은 `y 38`), 걷기 규칙(2.3)이 몸과 일치
- [ ] `left`와 `right`가 단순 반전이 아님
- [ ] `body_base`와 겹쳐 4방향 × 4프레임을 75ms로 재생했을 때 어긋남·미끄러짐 없음 — **최종 그림(12c)에서만 수동 확인**. 개발용 그림(12b)은 자동 검사만 (Claude Code 제안 채택)
- [ ] AI·외부 이미지는 `art:ingest`를 거친 `.pix` 원본에서 `art:build`로 만든 시트만 (7.1)
- [ ] 파일명·ID가 `<slot>_<name>` 규칙, `catalog.json` 항목 존재, 새 아이템은 서버 목록 추가보다 먼저 배포

**타일셋·공통**
- [ ] 타일셋 256×256, 인덱스와 `names` 일치, 9분할 세트가 3×3 인접
- [ ] `overhead`용 타일이 캐릭터 위에 그려질 때 가리는 범위가 의도와 일치
- [ ] PNG 압축 후 256 KB 이하, 메타데이터 없음
- [ ] `LICENSES.md`에 출처 기록
- [ ] 폰트: `scripts/fonts/check-font.py` 통과 — 한글 11,172자·ASCII 95자·호환 자모(원본 보유분) 수록, name ID 1/3/4/6/16에 예약 이름 "Galmuri" 없음, 256 kB 이하
