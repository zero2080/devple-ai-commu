# GRAPHICS — 그래픽 · 이미지 자산 스펙

> 문서 버전: 1.0 (2026-09-30)
> 상태: 확정 (팔레트 색 목록만 첫 아바타 제작 시 최종 고정)
> 용도: 도트 아트 자산을 **그리는 사람(또는 이미지 생성 AI)** 과 **불러 쓰는 코드(`game/`)** 가 공유하는 단일 기준. ROADMAP 12단계(자산 교체)의 완료 조건이며, 이 스펙에 맞지 않는 이미지는 받지 않는다.
> 관련: ARCHITECTURE 2장 (렌더링), DOMAIN 4.3 (MapData), CONVENTIONS 6장 (게임 레이어)

## 1. 공통 규격

| 항목 | 값 | 비고 |
|---|---|---|
| 스타일 | 90년대 16비트 콘솔풍 도트 아트 (SNES·GBA 시대), 3/4 탑다운 시점 | 등각(isometric) 아님 |
| 기본 단위 | **1타일 = 16×16 px** | `TILE_SIZE` |
| 원본 해상도 | **1x** (확대하지 않은 원본 픽셀) | 렌더 시 정수 배율(2x 기본)로 확대. 2x로 그린 원본은 받지 않음 |
| 파일 형식 | PNG, 8비트 RGBA (PNG-32), 투명 배경 | JPG·WebP·GIF 불가. 메타데이터 제거 |
| 색 공간 | sRGB, 감마 보정 없음 | |
| 안티앨리어싱 | **없음.** 모든 픽셀은 팔레트 색 그대로 | 반투명 픽셀 금지 (알파는 0 또는 255) |
| 외곽선 | 1px, 팔레트의 가장 어두운 색 계열 | 캐릭터·오브젝트 공통. 바닥 타일은 외곽선 없음 |
| 디더링 | 최소한만 (그라데이션 대용으로 남용 금지) | |
| 그림자 | 자산에 그리지 않음 | 필요 시 코드가 발밑 타원을 별도 그림 |

### 1.1 팔레트
- 프로젝트 전체 **단일 팔레트, 32색 이내**. 파일: `src/assets/palette.json` (`{ name, colors: string[] }`, hex)
- 시작 팔레트로 **Endesga 32** (Lospec 공개 팔레트, 자유 사용 — 정확도 중간, 12단계 착수 시 라이선스 재확인) 를 채택하고, 첫 아바타 제작 과정에서 색을 교체·확정한다. 확정 후에는 변경 시 모든 자산을 재검수한다
- 캐릭터 1종은 팔레트 중 **8색 이내**, 타일셋은 전체 팔레트 사용 가능
- 순수 검정 `#000000`·순수 흰색 `#ffffff`는 외곽선·하이라이트로도 쓰지 않는다 (팔레트의 근사색 사용). 예외: 코드가 그리는 UI 요소

### 1.2 렌더 전제 (코드 쪽 보장)
- `ctx.imageSmoothingEnabled = false`, `image-rendering: pixelated`
- 모든 그리기 좌표는 정수 픽셀. 서브픽셀 위치 금지
- 줌은 2x·3x·4x만. 뷰포트 최소 보장 크기 **20×15 타일** (2x에서 640×480 CSS px)

## 2. 캐릭터 스프라이트

### 2.1 규격
| 항목 | 값 |
|---|---|
| 프레임 크기 | **16×32 px** (가로 1타일, 세로 2타일) |
| 앵커 | 프레임 하단 중앙 `(8, 32)` = 캐릭터가 서 있는 타일의 바닥 중앙 |
| 몸 비율 | 2등신(치비). 머리가 위쪽 16px, 몸이 아래쪽 16px 안에 들어옴 |
| 여백 | 프레임 좌우 각 1px 이상 비움 (인접 프레임 번짐 방지) |
| 방향 | 4방향: `down`, `left`, `right`, `up` — **4방향 모두 별도 제작** (좌우 미러 금지: 비대칭 소품·머리 방향 때문) |
| 애니메이션 | 방향별 4프레임: `0` 서 있음(idle), `1` 왼발, `2` 서 있음(중간), `3` 오른발 |
| 걷기 재생 | `1 → 2 → 3 → 0` 순환, 프레임당 **75ms** (타일당 150ms 이동 = 2프레임/타일) |
| 자리비움 | 별도 프레임 없음. 코드가 idle 프레임에 알파 0.5 적용 |

### 2.2 시트 배치
아바타 1종 = PNG 1장 **64×128 px**. 행 = 방향, 열 = 프레임.

```
        col0     col1     col2     col3
row0    down/0   down/1   down/2   down/3
row1    left/0   left/1   left/2   left/3
row2    right/0  right/1  right/2  right/3
row3    up/0     up/1     up/2     up/3
```
프레임 `(dir, frame)`의 좌상단 = `(frame * 16, rowOf(dir) * 32)`

### 2.3 아바타 목록
- `avatarId` 형식: `char_NN` (`NN` = 01부터 두 자리). 파일: `src/assets/sprites/characters/char_NN.png`
- 초기 제공 **8종** `char_01` ~ `char_08`. 성별·피부색·복장이 고르게 분포하도록 하되 특정 실존 인물·IP 캐릭터를 닮지 않게 한다
- 추가 시 번호만 늘리고 시트 규격은 동일. 서버의 `avatarId` 검증 목록도 함께 갱신 (백엔드 결정 사항)
- 모든 아바타의 idle `down/0` 프레임은 로그인·프로필 카드의 **미리보기**로도 쓰인다 (3x 확대 표시)

### 2.4 atlas
`src/assets/sprites/characters/characters.atlas.json` 하나로 전체 아바타를 기술한다.
```ts
interface CharacterAtlas {
  frameWidth: 16;
  frameHeight: 32;
  anchor: { x: 8; y: 32 };
  directionRows: { down: 0; left: 1; right: 2; up: 3 };
  animations: {
    idle: { frames: [0]; frameMs: 0 };
    walk: { frames: [1, 2, 3, 0]; frameMs: 75 };
  };
  avatars: Record<string, { image: string }>;   // avatarId → 파일 경로
}
```
- 규격이 전 아바타 공통이므로 프레임 좌표 표는 두지 않는다. 좌표는 코드가 2.2 공식으로 계산
- `avatars`에 없는 `avatarId`가 서버에서 오면 코드는 `char_01`로 대체하고 `console.warn`

## 3. 타일셋

### 3.1 규격
| 항목 | 값 |
|---|---|
| 타일 크기 | 16×16 px |
| 시트 크기 | **256×256 px** = 16열 × 16행 = 256타일 (시트 1장/맵) |
| 인덱스 | `index = row * 16 + col`, 0부터. `-1` = 빈칸 |
| 여백·간격 | 없음 (타일이 빈틈없이 배치). 코드가 정수 좌표만 쓰므로 번짐 없음 |
| 파일 | `src/assets/tilesets/<tilesetId>.png` + `<tilesetId>.tileset.json` |

### 3.2 필수 타일 (맵 `main` 기준)
| 구역 | 내용 | 수량 |
|---|---|---|
| 바닥 | 잔디·흙·돌바닥·나무바닥 각 2~3변형 (단조로움 방지) | ~12 |
| 벽 | 9분할(상·하·좌·우·4모서리·내부) + 내부 모서리 4 | 13 |
| 문·창 | 열린 문, 창문 (장식) | ~4 |
| 가구·소품 | 테이블, 의자(4방향), 책장, 화분, 카펫(9분할), 램프, 게시판 | ~30 |
| 야외 | 나무(2×2, 위쪽은 `above` 레이어), 울타리, 바위, 꽃 | ~16 |
| 여유 | 향후 확장 | 나머지 |

- 2타일 이상 크기 오브젝트(나무·책장)는 **타일 단위로 분할**해 시트에 넣고 맵에서 조합한다. 캐릭터보다 위에 그려야 할 부분(나무 꼭대기, 지붕)은 `above` 레이어에 배치
- 벽·카펫 같은 9분할 세트는 시트에서 **3×3 블록으로 인접 배치** (맵 에디터 자동 타일 대응 여지)

### 3.3 tileset JSON
```ts
interface TilesetData {
  id: string;
  image: string;               // PNG 경로
  tileSize: 16;
  columns: 16;
  count: number;               // 실제 사용 타일 수 (≤ 256)
  names?: Record<number, string>;  // index → 사람이 읽는 이름 (디버그·에디터용, 선택)
}
```

## 4. 맵

- `MapData` 정의는 DOMAIN 4.3. 이 문서는 자산 관점의 규칙만 추가한다
- `tileset` 필드로 3장의 타일셋 ID를 참조 (맵당 1개)
- 레이어 구성 (그리기 순서):

| name | order | 내용 | 비고 |
|---|---|---|---|
| `floor` | below | 바닥. 모든 타일이 채워짐 (`-1` 없음) | |
| `objects` | below | 가구·벽·나무 밑동 등 캐릭터와 같은 높이 | 정적. y 정렬 없이 캐릭터 아래 |
| `overhead` | above | 나무 꼭대기·지붕·처마 | 캐릭터 위 |

- `collision`은 레이어와 독립. 벽·가구·나무 밑동 타일은 1, 카펫·문·꽃은 0
- 맵 `main`: **40×30 타일** (640×480 px), `spawn: {20, 15}`. 스폰 주변 5×5는 항상 통행 가능
- 맵 그림은 **레이어별 PNG로 미리 그려 오지 않는다.** 타일셋 + 인덱스 배열이 원본이며, 완성 이미지가 필요하면 코드가 렌더한다
- 맵 편집: 당장은 JSON 직접 편집. 타일 수가 늘면 Tiled(무료 맵 에디터)의 JSON 내보내기 → `MapData` 변환 스크립트 도입 검토 (12단계 이후)

## 5. 말풍선 · 닉네임 · UI

말풍선과 닉네임은 **DOM 오버레이**(ARCHITECTURE 2.3)라 이미지 자산이 아닌 CSS 스펙이다.

### 5.1 폰트
- 한글·영문·숫자를 모두 커버하는 **픽셀 폰트** 1종을 웹폰트로 동봉. 후보: Galmuri (OFL), DungGeunMo (OFL) — 라이선스는 채택 시 원문 확인 (정확도 중간)
- 폰트 크기는 **폰트의 기본 픽셀 크기 × 줌 배율**만 사용 (예: 11px 폰트 → 2x에서 22px). 비정수 배율 금지
- 픽셀 폰트가 글리프를 못 가진 문자(이모지·희귀 한자)는 시스템 폰트 폴백 허용. `font-family: 'PixelKo', system-ui`

### 5.2 말풍선 (`SpeechBubble`)
| 항목 | 공개 | DM |
|---|---|---|
| 배경 | 팔레트 밝은 회백색 | 팔레트 연한 파랑/보라 계열 |
| 테두리 | 2px(1x 기준 1px × 줌) 어두운 외곽선, 모서리 1px 깎음 | 동일 |
| 꼬리 | 하단 중앙, 캐릭터 머리 위 2px 지점을 가리킴 | 동일 |
| 최대 폭 | 12타일(192px × 줌). 초과 시 줄바꿈 | 동일 |
| 링크 버튼 | 하단, `↗ hostname`, 같은 폰트 | 동일 |

- 테두리는 CSS `box-shadow` 다중 그림자로 픽셀 외곽선을 그린다 (`border-image` 대신, 줌마다 정수 px)
- 말풍선 위치는 캐릭터 프레임 상단(앵커 y − 32px × 줌)에서 4px × 줌 위

### 5.3 닉네임
- 캐릭터 머리 위 2px × 줌 지점, 가운데 정렬, 폰트 5.1
- 배경 없이 어두운 외곽선(`text-shadow` 4방향 1px × 줌)
- **12단계에서 Canvas `fillText` → DOM 오버레이로 전환** (말풍선과 같은 레이어·폰트로 통일). 그 전까지 현재 플레이스홀더 유지. 화면 밖 캐릭터의 노드는 만들지 않는다

### 5.4 UI 아이콘
- 로그인·패널·운영자 콘솔의 아이콘은 **16×16 단색 픽셀 아이콘** SVG가 아닌 PNG 시트 `src/assets/ui/icons.png` (16열). 색은 CSS `mask-image`로 입힌다
- 필요 목록: 보내기, 닫기, DM, 그룹, 링크, 설정, 접속중, 자리비움, 경고, 검색

## 6. 파일 구조

```
src/assets/
├── palette.json
├── sprites/characters/
│   ├── characters.atlas.json
│   ├── char_01.png … char_08.png
├── tilesets/
│   ├── main.png
│   └── main.tileset.json
├── maps/
│   └── main.json              # MapData
├── fonts/
│   └── <PixelKo>.woff2 + LICENSE
└── ui/
    └── icons.png
```
- 자산 로딩은 `game/assets/loader.ts` 한 곳에서 (CONVENTIONS 6장). 이미지 `<img>`·`new Image()`는 loader 밖에서 금지
- 모든 PNG는 커밋 전 `oxipng`(또는 동급) 무손실 압축. 파일당 상한 256KB
- 자산 라이선스: 직접 제작 또는 CC0/OFL만. 출처·라이선스를 `src/assets/LICENSES.md`에 기록

## 7. 제작 발주 지침 (아티스트 · 이미지 생성 AI 공통)

자산을 요청할 때 아래를 그대로 전달한다. AI 생성물은 **참고용**이며, 최종본은 반드시 1.1 팔레트로 리컬러·픽셀 정렬 검수를 거친다.

```
스타일: 1990년대 16비트 콘솔 RPG(SNES 시대) 도트 아트, 3/4 탑다운, 2등신 치비.
해상도: 원본 1배. 캐릭터 프레임 16×32px, 타일 16×16px. 확대·안티앨리어싱·블러 없음.
팔레트: 첨부 palette.json의 32색만 사용. 캐릭터는 그중 8색 이내.
외곽선: 1px, 어두운 색. 그림자 없음. 투명 배경 PNG.
캐릭터: 4방향(아래·왼쪽·오른쪽·위) 별도, 방향당 4프레임(서기, 왼발, 서기, 오른발). 발은 프레임 맨 아래 중앙.
시트: 64×128px, 행=방향(아래,왼,오른,위), 열=프레임.
금지: 실존 인물·기존 게임/애니 캐릭터 유사, 텍스트, 로고, 그라데이션, 반투명 픽셀.
```

## 8. 검수 체크리스트

자산을 받을 때마다 확인한다. 하나라도 실패하면 반려.

- [ ] 크기가 정확히 규격(캐릭터 64×128, 타일셋 256×256)이고 배율이 1x
- [ ] 알파 채널 값이 0 또는 255만 존재 (반투명 픽셀 0개)
- [ ] 사용 색이 모두 `palette.json`에 있고, 캐릭터는 8색 이내
- [ ] 캐릭터 4방향 × 4프레임 모두 채워짐, 발 앵커가 `(8, 32)`에서 ±1px 이내
- [ ] 각 프레임 좌우 1px 여백에 픽셀 없음
- [ ] `left`와 `right`가 단순 미러가 아님 (소품 위치 확인)
- [ ] 걷기 4프레임을 75ms로 재생했을 때 발 미끄러짐 없음
- [ ] 타일셋 인덱스와 `names`가 일치, 9분할 세트가 3×3 인접
- [ ] `overhead`용 타일이 캐릭터 위에 그려질 때 캐릭터를 가리는 범위가 의도와 일치
- [ ] PNG 압축 후 256KB 이하, 메타데이터 없음
- [ ] `LICENSES.md`에 출처 기록

검수 자동화: 12단계에서 `scripts/check-assets.ts` (크기·알파·팔레트·여백 검사)를 만들어 CI에 넣는다.
