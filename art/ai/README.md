# AI 그림 생성 키트

아바타 레이어(기준 몸 1 + 아이템 42종)의 **최종 그림을 AI로 만들기 위한 컨텍스트**다 (사용자 결정 2026-10-01, ROADMAP 12b). 지금 저장소에 있는 그림은 Claude가 코드로 찍은 **개발용 그림**이고, 이 키트로 만든 그림이 같은 경로를 덮어쓴다 (12c). 타일셋 지시문은 12b-4에서 더한다.

규격 원문은 `docs/GRAPHICS.md`(1·2·7·8장)이고, 여기 내용은 생성 AI에게 주기 좋게 줄인 것이다. 둘이 다르면 GRAPHICS가 기준이다.

## 파일

| 파일 | 내용 |
|---|---|
| `briefs/<id>.md` | 아이템마다 하나 (자동 생성 `pnpm art:brief`). 무엇을·어디에 그리는지, 바뀌는 색, back 시트 여부, **이미지 모델용 영어 프롬프트**, 텍스트 에이전트용 글자 목록 |
| `glyphs.md` | `.pix` 팔레트 고정색 코드표 (자동 생성) |
| `../README.md` | `.pix` 텍스트 원본 형식 |
| `../templates/avatar-guide.png` · `key-colors.png` | 프레임 가이드·키 색 견본 (`pnpm art:templates`) |
| `../../src/assets/sprites/avatar/**` | 지금 쓰는 그림 (개발용). 자리·크기 참고 |

## 순서

1. 만들 아이템의 `briefs/<id>.md`를 연다
2. 아래 두 경로 중 하나로 그린다
3. `pnpm art:build` — `.pix`에서 PNG를 만들고 GRAPHICS 8장 자동 검수(`check:assets`)까지 돈다. 실패하면 메시지(`파일:줄: 이유` 또는 `아이템 (시트): 문제`)대로 `.pix`를 고친다
4. 눈으로 확인: `pnpm dev`로 띄워 옷장에서 색을 바꿔 보고(키 색이 제대로 칠해졌는지), 월드에서 4방향으로 걸어 본다(어긋남·미끄러짐 — 8장의 수동 항목)
5. `.pix`와 PNG를 함께 커밋한다 (PNG만 고치면 `check:assets`가 막는다)

### 경로 ① 이미지 생성 모델

1. 브리프의 `text` 블록(영어 프롬프트)을 그대로 넣고, 참고 이미지로 `avatar-guide.png`, `key-colors.png`, 기준 몸(`src/assets/sprites/avatar/body/body_base.png`), 그 아이템의 지금 그림을 함께 준다
2. 받은 PNG를 넣는다: `pnpm art:ingest <받은.png> --id <id>` (back 시트는 `--sheet back`, 한 방향만 받았으면 `--dir <방향>`)
   - 받을 수 있는 크기: 4방향 띠 96×40, 시트 96×160, 한 프레임 24×40의 **정수배**. 배율은 크기로 알아낸다 (`--scale N`으로 지정 가능)
   - 배경: 투명, 또는 네 모서리와 같은 단색이면 그 색을 투명으로 본다
   - 축소는 칸마다 가장 많은 색, 색은 그 레이어가 쓸 수 있는 키 색·팔레트 색 중 가장 가까운 색으로 바꾼다
   - 기존 `.pix`가 있으면 같은 시트(front/back)만 바꾼다
3. 이미지 모델은 격자·정확한 hex·프레임 일관성을 자주 놓친다. 그래서 정리 결과는 `.pix` **텍스트**로 남기고, 어긋난 칸·잘못 잡힌 색은 사람이나 텍스트 에이전트가 고친다. 격자에 맞지 않은 그림(비정수 확대, 블러, 어긋난 위치)은 편집기에서 맞춘 뒤 넣는다. JPEG는 받지 않는다

### 경로 ② 텍스트 에이전트 (Claude 등)

에이전트에게 이 파일, 해당 브리프, `../README.md`(형식), `glyphs.md`를 주고 아래처럼 시킨다.

```text
너는 16비트 콘솔 RPG 도트 아티스트다. art/ai/briefs/<id>.md의 아이템을 art/README.md의 .pix 형식으로
art/source/avatar/<slot>/<id>.pix에 그려라. 방향마다 서기 1장(24×40), 4방향을 각각 그린다(좌우 반전 금지).
기준 몸(art/source/avatar/body/body_base.pix) 위에 겹친다고 생각하고 자리를 맞춘다. 바뀌는 부분은 브리프의 키 색 글자만,
나머지는 외곽선 o와 팔레트 코드 4색 이내. 다 쓰면 pnpm art:build를 돌리고, 실패 메시지가 없어질 때까지 고친다.
```

## 모든 레이어에 공통인 규칙 (GRAPHICS 요약)

- 원본 1배. 프레임 24×40, 앵커는 아래 가운데 (12, 40) = 서 있는 타일 바닥 가운데
- 2등신: 머리 y 8–23(폭 약 14px), 몸통 y 24–31, 다리 y 32–39, 발바닥 y 39. 몸 박스 x 4–19, y 8–39
- 위 여백(y 0–7)은 **모자만**, 좌우 여백(x 0–3, 20–23)은 **손 소품·머리숱·모자 챙만**
- 4방향(down·left·right·up)을 각각 그린다. 좌우 반전 재사용 금지
- 서기 1장만 그린다. 걷기 프레임은 빌드가 만든다 (머리·몸통 1px 흔들림, 다리 교대 — `../README.md` "걷기 파생")
- 바뀌는 부분은 키 색만, 그 밖은 팔레트 색만. 외곽선 1px `#181425`. 외곽선 빼고 고정색 4색까지
- 안티앨리어싱·반투명·그림자·글자·로고 금지. 실존 인물·기존 게임/애니 캐릭터와 닮지 않게
- 레이어는 정해진 순서로 겹친다 (뒤 → 앞): 머리 back, 모자 back, 손 back, 몸, 하의, 신발, 상의, 머리, 얼굴, 모자, 손. 모자는 머리카락 위에 그려지므로 정수리를 충분히 덮는다
